# Локальный debug-набор

`scripts/fixtures/debug-space.json` — сценарий из трёх синтетических участников:

| Участник | Роль магазина | Отношения | Администратор |
| --- | --- | --- | --- |
| Алекс | dominant | Верхний Вики | Да, первый участник |
| Вика | switch | Нижняя Алекса, верхняя Луны | Нет |
| Луна | bottom | Нижняя Вики | Нет |

Это вымышленные сведения для локального интерфейса. Профильные метки не заменяют
права отношений. Алекс не получает полномочий в отношении Луны через Вику.

Заполняются все шесть разделов профиля, предпочтения со ссылками на справочники,
условия и табу. Здоровье и дневники остаются личными. Выбранные разделы профиля
открыты только непосредственным партнёрам. Для каждого участника есть заполненная
анкета; для каждой связи — два принятых правила, заявка на изменение правила,
четыре ритуала с разными состояниями, заявка на пропуск, два шаблона наказаний и
назначение с комментарием. Даты вычисляются по текущему дню Europe/Madrid.

Магазин импортирует весь `scripts/fixtures/rewards.json` (103 товара), изображения
берутся из репозиторного static. Стартовое начисление: Вике 1500, Луне 1200 монет.
В каждой связи созданы четыре покупки: ожидающая решения (120), одобренная (80),
погашенная (60) и отклонённая (100, резерв возвращён). После этих примеров:

| Участник | Доступно | В резерве | Общий остаток |
| --- | --- | --- | --- |
| Вика | 1240 | 120 | 1360 |
| Луна | 940 | 120 | 1060 |

Покупки и переходы статусов выполняются через обычный API приложения. Стартовые
монеты записываются штатным сервисом ledger: скрипт не повышает shop-role Вики
ради доступа к API ручных начислений. Вика может покупать у Алекса и согласовывать
покупки Луны. Уведомления включены только внутри приложения; приглашения анкет
создаются с `deliver=false`. Скрипт не отправляет Telegram-сообщения.

## Пересоздание

Применять только к отдельной локальной БД, имя которой заканчивается на `_test`,
после миграций до актуальной схемы. Остановить debug API на время пересоздания.
Установить `TEST_DATABASE_URL` в окружении; не сохранять рабочие секреты в git.

```sh
uv run --project backend python scripts/seed_debug_space.py \
  --reset \
  --bot-token-file artifacts/deployment/ui-context/runtime/bot-token \
  --keyring-file artifacts/deployment/ui-context/runtime/keyring.json
```

Без `--reset` разрешена только пустая таблица пользователей. Сброс проверяет не
только известные синтетические Telegram ID, но и имена. При любом неизвестном
участнике сброс прерывается. На существующей БД до удаления создаётся полный
`pg_dump -Fc` в игнорируемой `.superpowers/debug-backups` с правами 0600; ошибка
резервирования останавливает сброс. Повторная проверка под блокировкой защищает
от изменения списка участников во время резервирования.

Сброс удаляет связанные пользовательские записи, а не только аккаунты, затем
заново выполняет сценарий. Справочники сохраняются и актуализируются их штатными
фикстурами. Сбой заполнения не откатывает уже выполненные API-запросы: исправить
причину и повторить guarded reset либо восстановить dump в остановленную тестовую
БД через `pg_restore --clean --if-exists`. При восстановлении сохранить тот же
keyring. Не использовать этот инструмент для основной БД или реальных участников.

## Запуск после заполнения

```sh
uv run --project backend python scripts/debug_server.py
```

API слушает только `127.0.0.1:8002`, debug-доступ доступен только локально в
`development`. Web использует текущий dev-сервер `http://127.0.0.1:5176`.
Перезапуск API **не** пересоздаёт пользователей и сохраняет изменения интерфейса.
После сброса старые сессии недействительны: выбрать Алекса, Вику или Луну в
локальном debug-входе. Отдельный `scripts/e2e_server.py` сохраняет прежний набор
из 12 участников для существующих автоматических E2E-тестов.

## Проверка

```sh
uv run --project backend pytest backend/tests/integration/test_debug_space_fixture.py -q
uv run --project backend ruff check scripts/seed_debug_space.py scripts/debug_server.py \
  backend/tests/integration/test_debug_space_fixture.py
```

Интеграционные тесты используют `TEST_DATABASE_URL` и очищают выделенную тестовую
БД через штатную pytest fixture. Не запускать их против БД живого UI preview.
