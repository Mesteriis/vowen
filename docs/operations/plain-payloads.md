# Хранение прикладных данных без шифрования

Решение владельца от 2026-10-18: прикладное шифрование payload отключено. Новые данные дневника, анкет, соглашений, правил, ритуалов, вложений, наград, наказаний и заявок хранятся открыто. API по-прежнему проверяет владельца, читателей, участников и полномочия при каждом доступе. Парольные/токенные хэши, HTTPS и Android Keystore токенов не изменены.

## Формат и совместимость

Для совместимости существующие поля `key_id`, `nonce`, `ciphertext` и интерфейс `PayloadCipher` оставлены. В новом формате `key_id=plaintext-v1`, `nonce` пустой, `ciphertext` содержит исходные байты без AES, кодирования или обфускации. Проверка типа и версии оболочки остаётся. Криптографической привязки открытых байтов к UUID нет; целостность и права доступа обеспечиваются приложением и БД.

AES-GCM оставлен только как декодер ранее записанных данных. Конструктор не открывает keyring, запись/чтение нового формата не зависят от его наличия. `appctl instance init` больше не создаёт ключи. `init_keyring` — вспомогательная функция для исторических тестов/инструментов, она не используется для новых production payload.

## Перевод существующей базы

1. Остановить API, workers и bot, чтобы исключить запись старым процессом после перевода.
2. Сделать закрытую резервную копию базы и сохранить исходный keyring для восстановления старых копий.
3. Явно задать `DATABASE_URL` нужной базы и `DATA_KEYRING_FILE` исходного keyring. Применить `uv run --project backend alembic -c backend/alembic.ini upgrade head`.
4. После успешной миграции 0035 запустить обновлённые процессы. Для новой пустой базы keyring не нужен.

Compose-сервис `migrate` получил read-only mount каталога secrets, чтобы прочитать исходный ключ при обновлении старой базы. Существующие секреты не удаляются и не перегенерируются.

Миграция обрабатывает 15 известных типов payload в одной транзакции, блокирует их таблицы и читает по одной строке, включая бинарные вложения. Временно отключается только триггер неизменяемости `currency_entries`, он включается до commit. Меняется лишь представление комментария, суммы и события не переписываются. Ошибка ключа, повреждённого ciphertext или неизвестного формата отменяет всю транзакцию и изменения триггера. Очищенные nullable payload остаются null. Повторный запуск не меняет открытые байты и не требует ключей.

Откат ревизии сохраняет plaintext и не включает шифрование обратно. Для запуска старого бинарника, который знает только AES, требуется восстановить исходную БД вместе с исходным ключом; одного downgrade недостаточно. Старые зашифрованные резервные копии по-прежнему требуют своих ключей. Шифрование системы резервного копирования этим решением не изменялось.

## Проверено локально

- Все 287 backend-тестов прошли; дополнительно 16 целевых проверок после последней правки, включая работу приватного дневника без файла ключей.
- Миграционный тест конвертирует все 15 типов, проверяет повтор без ключа, сохранность байтов и неизменяемость ledger; повреждение последнего типа откатывает предыдущие обновления и состояние триггера.
- 32 Web Vitest, Web typecheck и scoped mypy/ruff прошли.
- `vowen_design_test`: перед миграцией закрытая копия, после 0035 зашифрованных payload осталось 0. Локальный API перезапущен. Основная `vowen` и удалённые серверы не изменены.
- Без сборок и коммитов. Живой Telegram и Android-устройство не проверялись.
