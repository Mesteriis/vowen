# Профиль и настройки пространства

## Личный профиль

Открывается по личной аватарке; из основного меню убран. В шапках с контекстом отношений личная аватарка теперь отдельная кнопка, а соседний переключатель продолжает выбирать партнёра.

Табы профиля: «Личные данные», «Уведомления», «Сессии». Имя, язык, часовой пояс и метки самоописания сохраняются существующим PATCH `/me/preferences` с optimistic version. Уведомления используют прежний API и revision; подключение бота не происходит автоматически. Сессии остаются только собственными; перед отзывом есть подтверждение. Все личные функции доступны обычным участникам, независимо от администратора.

Старые ссылки `#notifications` и `#sessions` открывают соответствующий таб профиля. Переключение табов сохраняет локальный черновик; явное обновление с сервера сбрасывает его, как и ранее.

## Общие настройки

Отдельная страница `#settings`. Ссылка находится внизу бокового меню, на телефоне — в конце «Ещё». Пункт виден только администратору. При прямом открытии обычный участник видит отсутствие доступа без списка участников/действий. Пока в настройках есть только управление администраторами.

Администратор может назначить дополнительного администратора, сохранив свои права, либо передать свои права другому участнику и потерять собственные. Обе операции требуют подтверждения с именем адресата. После передачи клиент обновляет `/me`, убирает настройки и возвращает пользователя в профиль.

## Роль и серверные границы

Роль `users.is_admin` независима от D/s, shop_role и свободных меток профиля. Первый созданный участник автоматически получает её; следующие — только через администратора. Для уже существующей базы миграция 0026 выбирает самого раннего участника по `(created_at,id)`, остальные остаются обычными участниками. Если ранние timestamps одинаковы, tie-breaker — id. Автопровижининга при Telegram-входе по-прежнему нет.

GET `/administration` и POST `/administration/administrators/{user_id}/grant|transfer` каждый раз проверяют актуальную активность и is_admin пользователя в БД. Клиентский флаг только управляет отображением. В API профиля `is_admin` менять нельзя. Возвращаемые административные сведения ограничены id, отображаемым именем и ролью активных участников.

Провижининг, изменения активности оператором, чтение административного списка и изменения прав используют блокировку singleton-строки administration_state. Команды проверяют expected_revision. Передача атомарно назначает нового администратора и снимает права с текущего; история записывается в administrator_events в той же транзакции. Конкурентные передачи не снимают права у всех администраторов. Повторное назначение уже назначенного администратора с текущей revision — no-op. После потери роли прежний bearer-токен сразу теряет административные полномочия на следующем запросе.

Администратор не получает доступ к чужим дневникам, сессиям, уведомлениям либо полномочиям в отношениях. Операторская CLI-деактивация по-прежнему может отключить участника независимо от роли; эта операция не доступна через новые настройки. Повторное включение через CLI остаётся способом восстановления в таком случае.

## Проверки

30 PostgreSQL/contract-тестов прошли: первые конкурентные создания, запрет самоповышения и меток как прав, grant/transfer, повторы, конфликт revision, немедленная потеря доступа, недоступный/собственный адресат, атомарность аудита, авторизация, профиль, CLI и приватность дневника. Mypy — новые административные сервис/роутер и provisioning; ruff — изменённые Python-файлы. Web typecheck и 28 Vitest прошли.

В браузере проверены администратор и обычный участник, профиль через аватарку и из шапки ритуалов, персональные уведомления, запрет прямой ссылки на настройки, мобильное меню, оба окна назначения/передачи с отменой; 4 размера без горизонтального overflow. Права существующим участникам через браузер при QA не назначались и не передавались; эти изменения проверены на изолированной тестовой базе.

Android: DTO, API/callbacks, личные табы, отдельные настройки, администраторские действия и навигация обновлены в исходниках; сборка и устройство не проверены по пользовательскому ограничению.

Локальная design-база мигрирована до 0026 после отдельной резервной копии; данные не пересоздавались. При первой попытке миграции неверная переменная окружения направила команду в локальную базу vowen; добавленная миграция 0026 там отменена до 0025, перед отменой сделана закрытая резервная копия. Прод/удалённые серверы не менялись. Сборки, коммиты и деплой не выполнялись.
