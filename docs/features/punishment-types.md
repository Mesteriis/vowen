# Типы наказаний

Наказания принадлежат прямым отношениям с действующими полномочиями `discipline.propose`. Создание и изменение условий доступны верхнему участнику (Dominant либо Switch в верхнем контексте), изменение существующей записи — её автору. Глобальная роль магазина не используется как разрешение. Нижний не редактирует условия. Отдельный шаг согласия, отказа или оспаривания наказания не моделируется. Общие настройки отношений остаются самостоятельным механизмом доступа.

- `physical`: девайс, часть тела, положительное целое количество ударов и целая сила воздействия 1–10.
- `ban`: текстовое описание и положительное целое число дней.
- `other`: текстовое описание.

Описание, предлагаемые условия и имеющиеся связи с правилом/ритуалом сохраняются. Срок, связи и проверяющие доступны в дополнительных настройках Web. Параметры сохраняются в зашифрованной неизменяемой версии и отображаются в записи и истории. Создание и изменение условий устанавливают `planned`. Исполнитель может сразу начать выполнение: `planned → in_progress → completed → confirmed` (последний шаг выполняет назначенный проверяющий). Автор может отменить наказание. Шаг согласия отсутствует; API не принимает действия `accept`, `decline`, `dispute`. Старые `proposed`/`accepted` допускают прямое начало, исторические события не переписываются.

## Справочники

`GET/POST /api/v1/discipline-records/dictionaries/{relation_id}/{kind}`, где `kind=device|body_part`. GET доступен прямым участникам при текущих полномочиях отношений; добавление — верхнему. Чужие отношения возвращают 404, нижний при добавлении — 403. Пауза блокирует добавление. Данные не передаются по цепочке отношений.

Начальные девайсы: Стек, Падл, Рука, Плеть. Начальные части тела: Спина, Ягодицы, Ноги, Живот, Грудь, Руки. Верхний может добавить своё название (1–100 символов); пробелы нормализуются, повтор без учёта регистра не создаёт дубликат. Добавления шифруются и сохраняются в PostgreSQL отдельно для каждых отношений. Удаления справочника в этой версии нет. Сериализация изменений защищена блокировкой отношений и уникальным ограничением.

Миграция 0023 создаёт `discipline_dictionary`. Существующие зашифрованные записи без новых полей читаются как `other`. Миграция 0024 добавляет статус `planned` в ограничение БД; общая ревизия схемы — 0024. Контракт OpenAPI и DTO Web/Android обновлены.
