# Wiki — библиотека знаний

Общая для экземпляра энциклопедия практик, поз и девайсов и самостоятельные статьи.
Выбранные отношения и личная пауза не фильтруют библиотеку. Дневники, профили и
ответы анкет не импортируются.

## Доступ и редакции

Активный участник читает опубликованные материалы; без сессии API возвращает401.
Создание, редактирование, разделы, импорт, архив и история доступны администраторам
пространства, независимо от D/s-роли. Сервер проверяет права на каждой операции.
Черновые и архивные страницы отсутствуют в поиске, дереве, related-списках и
прямом member-ответе (404). Пустые разделы видны без скрытых счётчиков.

Сохранение создаёт неизменяемую редакцию. «Опубликовать» фиксирует конкретную
сохранённую редакцию; последующая правка не меняет публичные название, текст,
раздел и связи. Архив скрывает публикацию, восстановление возвращает прежний
черновик и публикацию. Физического удаления страниц нет.

Admin команды используют expected_version; stale-запись409. Отзыв admin-роли403.
В обоих случаях открытый редактор сохраняет текст в памяти. При переходе с
несохранёнными изменениями Web показывает локальное окно подтверждения; обновление
самой страницы защищено штатным beforeunload. Draft не пишется в browser storage.

## Навигация

Wiki находится в основном меню, на телефоне — в «Ещё». Дерево — слева на большом
экране, на телефоне — панель «Разделы». Хлебные крошки возвращают к разделу,
оглавление ведёт к заголовкам. URL: `#wiki?page=UUID&section=UUID&q=...`.
Фон раздела прозрачный, текущий бархат/параллакс сохраняется.

В справочниках у опубликованных материалов есть ссылка «Статья в Wiki». Web
получает адрес от сервера, не вычисляя UUID по правилам фикстур. Ошибка загрузки
ссылок не скрывает справочник и отображается отдельно; смена справочника
отбрасывает устаревший ответ. Мобильная ссылка имеет область нажатия 44 px.
Android получил такой же серверный маршрут и переход к выбранному материалу;
debug-компиляция, JUnit и переходы проверены на QA-эмуляторе Android API 36
при ширине 390 и 1200 dp. Физическое устройство не проверялось.

Администратор переключает библиотеку/черновики/архив, создаёт статью либо
энциклопедическую страницу с одним основным объектом. Дополнительные связи
выбираются из справочников; основные ссылки уникальны и защищены FK RESTRICT.
Редактор поддерживает Markdown, предпросмотр, источники и локальную миниатюру.
Управление разделами использует явное сохранение и выбор родителя без drag-and-drop.
Максимальная глубина8; цикл запрещён. Исторически используемый раздел нельзя
удалить, даже если все текущие страницы перенесены: возвращается SECTION_IN_USE.

## Импорт

«Добавить из справочников» — явный admin POST `/api/v1/wiki/admin/seed-references`.
Он создаёт отсутствующие короткие карточки из текущих references, с UUIDv5,
сохраняя существующие описания/редакционное происхождение. Невалидные старые URL и
недоступные миниатюры не копируются. Полные авторские статьи автоматически не пишутся.
На текущем fixture-наборе создаётся261 карточка (93практики/106поз/62девайса).
Повтор пропускает существующие, включая изменённые и архивные страницы; добавленные
позже reference-записи получают новые карточки. Сервер внешние URL не скачивает.

## API

Member: GET `/api/v1/wiki/tree`, `/pages/{uid}`, `/search`, `/reference-links/{kind}`.
Последний маршрут принимает один из 17 видов справочников и возвращает только
пары `reference_uid` / `page_uid` для существующих опубликованных неархивных
материалов. Для практик/поз/девайсов используется реальная основная FK, включая
авторские страницы; для остальных видов — каноническая статья записи. Черновые
поля, заголовки и содержимое этим ответом не раскрываются.
Search принимает q≤200, section_uid (включает потомков), offset≥0, limit1–50;
сопоставление подстроки case-insensitive, `%` и `_` являются обычными символами.

Admin prefix `/api/v1/wiki/admin`:

- POST/GET `/pages`; GET-list state=drafts|published|archived, offset/limit≤50;
- GET/PATCH `/pages/{uid}`; POST `/pages/{uid}/publish`, `/archive`;
- GET `/pages/{uid}/revisions` и `/pages/{uid}/revisions/{revision_uid}`;
- POST `/sections`, PATCH/DELETE `/sections/{uid}`;
- POST `/seed-references`.

Удаление раздела принимает expected_version и expected_tree_version в query.
Управление деревом сериализовано singleton-строкой PostgreSQL; порядок блокировок
записи: AdministrationState → WikiTreeState → WikiPage. Это тот же admin-lock,
который использует передача прав. Каждая команда транзакционна.

## Разметка и ограничения

Заголовок160, summary600, body100000 символов; до50 дополнительных ссылок каждого
вида и20источников. Источники http/https без credentials/некорректного порта.
Миниатюра — существующий raster-файл в `static/web`, URL-путь от корня.
Контейнер backend содержит ту же статику в `/app/static/web`;
`VOWEN_STATIC_ROOT` задаёт серверный каталог проверки файлов (локально по умолчанию
используется `static/web` репозитория). Выход через `..` и symlink запрещён.
CommonMark: заголовки, абзацы, списки, emphasis/strong, цитаты, code и безопасные
ссылки. HTML отображается текстом; img/iframe/scripts/data/file/javascript не
исполняются и не загружаются. Web строит Vue-узлы из разрешённых tokens, без v-html;
Android строит Compose из AST, без WebView. Поисковые строки и содержимое не логируются.

Web: markdown-it15.0.3, pinned lockfile (15ветка имеет собственные типы).
Android: commonmark-java0.24.0 зафиксирован в Gradle lockfile. После отдельного
разрешения на Android-проверку debug APK собран, 30 JUnit тестов прошли.
Два Compose-теста переходов/ошибки прошли на QA-эмуляторе API36 при 390×844
и 1200×1600 px / density160. Проверяется реальный UI/state/JSON transport;
сетевая доставка в этих тестах синтетическая. Полный live-корпус отдельно
проверен через member API. Физическое устройство и release APK не проверялись.

## Миграция и локальная работа

Alembic0051 после0050 создаёт только Wiki-таблицы и четыре корня, не импортирует
карточки. Перед preview upgrade делать закрытый backup. Downgrade0051→0050
удаляет Wiki целиком и применим лишь к disposable scratch БД либо после backup;
для сохранения материалов нужен restore из backup. Прежние таблицы не изменяются.

Проверки: `uv run --project backend pytest backend/tests -q`, отдельно
`uv run --project backend pytest scripts/tests -q`; TEST_DATABASE_URL обязан
указывать на выделенную локальную `_test` БД. `pnpm --dir web test`, `typecheck`,
`lint` не требуют production-сборки. Контракты обновляются `make contracts`.
Продакшен и существующие участники на сервере этим изменением не затронуты.
## Русские редакционные статьи

В дополнение к коротким карточкам справочников поставляется 49 самостоятельных
обзорных статей: динамика и договорённости, практики, позы и девайсы, забота,
сексуальное здоровье и приватность. Это авторские редакционные тексты Vowen,
а не переводы внешней энциклопедии. В медицинской обзорной статье указаны
проверенные страницы ВОЗ и NHS; в статье о предварительном обсуждении — NCSF.
Остальные тексты не заявлены как медицинские или исторические исследования.

Фикстуры находятся в `backend/src/vowen/modules/wiki/fixtures/ru/v1/`:
`manifest.json` содержит названия, аннотации, рубрики, источники и коды связей;
`articles/*.md` — полные тексты. Ссылки на справочники при импорте разрешаются
в конкретные UUID; отсутствующие или неоднозначные коды отменяют всю транзакцию.

После миграций и загрузки справочников выполнить явный импорт от существующего
активного администратора (перед этим сделать резервную копию целевой БД):

```sh
# DATABASE_URL передаётся через окружение, без сохранения секрета в репозитории.
uv run --project backend python scripts/import_wiki_editorial.py --actor ADMIN_UUID
```

Импорт сразу публикует отсутствующие статьи и создаёт четыре подрубрики в
«Статьях». UUID не зависит от номера редакционной поставки. Повторное применение
не меняет существующие страницы, их черновики, разделы, публикации и архивный
статус. Обновления текстов после импорта проходят через обычный редактор Wiki.
Импорт не запускается автоматически при старте и не меняет участников.


### Развёрнутые карточки девайсов

Полные тексты для всех 62 исходных девайсов находятся в
`backend/src/vowen/modules/wiki/fixtures/ru/devices-v1/`. Каждая карточка описывает
назначение, особенности конструкции, отличия и сведения для выбора/ухода.
Это обзорные редакционные тексты без схем телесного воздействия или универсальных
параметров применения. В двух карточках указаны отдельные руководства производителей
как примеры документации конкретных изделий, а не правила для всего класса.

После загрузки справочников запустить от существующего активного администратора:

```sh
uv run --project backend python scripts/import_wiki_editorial.py --actor ADMIN_UUID --devices
```

Импорт создаёт отсутствующие страницы и обновляет только исходные заглушки.
Для обновления одновременно необходимы канонический UUID, версия1, ровно одна
редакция, совпадение draft/published и полное совпадение документа с первоначальной
заглушкой. Перемещённые, изменённые, черновые и архивные страницы сохраняются.
Старая редакция остаётся в истории; UUID и миниатюра сохраняются. Новые редакции
содержат реальные связи PracticeDevice. Повторный импорт пропускает обновлённые
страницы. Неоднозначные/отсутствующие коды отменяют транзакцию.

Обычный импорт «Добавить из справочников» остаётся missing-only и не выполняет
это обновление автоматически. Данный шаг запускается отдельно и явно.

### Развёрнутые карточки практик

Все93 практики исходного справочника имеют отдельные русские тексты в
`backend/src/vowen/modules/wiki/fixtures/ru/practices-v1/`: определения, отличия и
контекст обсуждения. Всего12 356слов, минимум124слова и три раздела на карточку.
Определения интимных форм нейтральные, без пошаговых техник; обзорные тексты не
заменяют инструкции к изделиям или индивидуальную медицинскую консультацию.
Для отдельных тем указаны NCSF, NHS и Planned Parenthood.

```sh
uv run --project backend python scripts/import_wiki_editorial.py --actor ADMIN_UUID --practices
```

Режимы --devices и --practices взаимоисключающие; без них импортируются прежние

канонические UUID исходного импорта; missing-категории создаются с проверкой
глубины дерева. Новые редакции связываются с девайсами через PracticeDevice.

uv run --project backend python scripts/import_wiki_editorial.py --actor ADMIN_UUID --poses

### Источники и обновление редакционных статей

Все самостоятельные статьи (сейчас 49) содержат раздел «Источники и пояснения» с
кратким русским пересказом конкретного тезиса и прямой ссылкой. Это авторские
материалы с пересказами, а не полные переводы чужих статей. Использованы 27
проверенных документов: определения и памятки NCSF, сведения NHS/ВОЗ/клиник,
материалы EFF, образовательная терминология и документация производителей.
Любительская подборка Gorean Codex обозначена как литературный источник,
а не универсальный BDSM-стандарт. Технические указания производителя не
распространяются автоматически на другие марки. У EFF указаны авторство,
адаптация на русский язык и CC BY 4.0 со ссылкой на условия использования.

`fixtures/ru/v1/source-review.json` хранит издателя, URL, дату проверки,
ограничения применимости и связи источников со статьями. Ссылки, не давшие
доступа к полному тексту, не использованы как проверенные источники. Реестр
относится к самостоятельным статьям; он не объявляет независимую проверку
каждого исторического названия и назначения всех 261 справочных карточек.

Обычный импорт остаётся missing-only. Для уже загруженной прежней редакционной
поставки использовать отдельный явный режим:

```sh
uv run --project backend python scripts/import_wiki_editorial.py --actor ADMIN_UUID --refresh-editorial
```

Он создаёт отсутствующие статьи и обновляет только прежние оригинальные
публикации: канонический UUID, версия 1, одна редакция, draft=published,
отсутствие архива, совпадение SHA-256 тела и всех метаданных с сохранённой
поставкой `upgrade-baselines.json`. Связи сравниваются как множества UUID,
поскольку порядок строк таблиц связей не является содержанием статьи.
Правки тела, заголовка, аннотации, миниатюры, источников, раздела или связей,
черновики и архив пропускаются. Старая редакция остаётся в истории. Повторный
импорт не добавляет редакций. Администратор и блокировка Wiki проверяются
на сервере; схема и API-контракт не меняются.

статей. В реестре source-review.json теперь 27 внешних документов.

### Материалы всех справочников и прямые ссылки

Область покрытия — все 17 видов справочников и 438 записей фикстур, а не только
практики, позы и девайсы. План и честный остаток: `docs/wiki/coverage-plan.md`,
`docs/wiki/coverage-current.json`. `scripts/check_wiki_coverage.py` проверяет
структуру поставки и возвращает 1, пока есть пробелы; наличие источника в JSON
само по себе не доказывает его релевантность или актуальность.

Новый явный режим `scripts/import_wiki_editorial.py --actor UUID --catalogues`
добавляет только отсутствующие публикации из `catalogues-v1`. Требуется ранее
импортировать справочники, исходные материалы практик/поз/девайсов и обзорные
статьи: ссылки на отсутствующие или неопубликованные цели отклоняют всю
транзакцию. Связь с записью задаётся проверяемой парой `kind` + `uid` в manifest;
публичная страница имеет стабильный UUID и обычный вид `article`. Новых таблиц
или универсальной полиморфной связи в БД не вводится. Ручные правки, черновики,
архив и существующие редакции повторный импорт не меняет.

Корпус содержит 138 материалов: форматы взаимодействия (3), места (6), виды
отношений (8), составы участников (10), часовые пояса (24), категории практик
(13) и поз (14), половые характеристики (3), гендер (7), ролевые сценарии (12),
материалы (15), части тела (23). Указатели категорий перечисляют все 199 реальных участников
групп; состав проверяется по FK фикстур. Определения внутренних категорий
обозначены как авторские, внешние руководства не объявляются источником нашей
классификации. Для часовых поясов приведены идентификатор, регион и сравнение
с другой зоной; нет обещания постоянной разницы часов или автоматического
изменения уже созданного расписания. Источники IANA отделены от советов по
планированию.

Markdown поддерживает только точный внутренний адрес `#wiki?page=UUID`, без
дополнительных параметров. В Web ссылка открывается в текущей вкладке; заголовок
новой статьи получает фокус и попадает в видимую область. Якоря оглавления
сохраняют прежнее поведение. Android распознаёт тот же адрес и передаёт UUID
в навигацию читателя; предпросмотр редактора не уводит пользователя с черновика.
Схемы javascript, произвольные маршруты и некорректные UUID не разрешаются.


Определения идентичности сопоставлены с ВОЗ и PFLAG; из гендера не выводятся
анатомия, D/s-роль и полномочия. Ролевые сценарии имеют авторские определения
и сравнения, руководства NCSF указаны только для подготовки разговора. Материалы
сверены с профильными публикациями Canadian Conservation Institute; музейные
рекомендации не выдаются за инструкции по интимному применению. Для латекса
использован первичный источник HSE. Анатомические карточки ссылаются на
конкретные главы OpenStax, определения написаны кратко своими словами; тексты,
иллюстрации и упражнения учебника не копируются. Для промежности проверена
отдельная глава о мышцах тазового дна, а не неподходящий обзор репродуктивной
системы.

Аудит отдельно отмечает пустые описания и описания, дословно повторяющие
название без учёта регистра/пунктуации. Непустое поле ещё не доказывает
содержательного описания; семантическая проверка остаётся отдельной задачей.

### Здоровье и аллергены

Дополнительный корпус расширен до 177 материалов всех 14 видов, дополняющих
практики/позы/девайсы. Добавлены 23 состояния здоровья и 16 аллергенных записей.
Они используют 37 отдельных профильных URL NHS, HSE и DermNet. Реестр
catalogues-v1/source-review.json содержит 56 документов с издателем, областью
применения и датой проверки. Различены диагноз и индивидуальные ограничения,
латексные белки и ускорители резины, раздражение и контактная аллергия,
вещество и подтверждённая аллергия участника. Caine mix описана как тестовая
смесь, а не аллергия на все местные анестетики. Нет дозировок, домашних
аллергопроб или медицинского допуска к практике по названию состояния.

Таким образом, отдельные материалы существуют для всех 438 записей 17
справочников. Это не завершает проверку качества: у старых карточек ещё нет
части источников и явных переходов, а некоторые описания самих справочников
повторяют название. Нужны отдельное защищённое обновление и полный аудит.

### Предметная проверка прежних карточек практик

Исторический корпус practices-v1 сохранён. Наложение practice-reviews-v1
содержит проверки всех 93 практик: виды близости, устройства и дистанционные
форматы, роли/образы, телесные/сенсорные темы, забота и групповые взаимодействия. Каждая запись хранит исходные метаданные и SHA-256 тела,
проверенные источники с областью подтверждения, намеренно выбранные сравнения
с другими практиками и обзорную статью. Итоговая поставка вычисляется через
load_reviewed_practice_articles; аудит использует именно её. Исходные тексты
не подменяются скрытой правкой исторического корпуса.

Явная команда --refresh-practices применяется после импорта исходных практик
(--practices) и обзорных статей (режим по умолчанию). Она не создаёт отсутствующие
практики. Проверяются администратор, общая блокировка Wiki и блокировка страницы.
Обновляется только точное исходное тело/метаданные: прямая публикация версии 1
либо последовательность исходная заглушка → исходная статья версии 2. Для второй
ветки дополнительно проверяется документ заглушки. Черновик, архив, перемещение,
изменённые источники/FK/миниатюра и любая другая история пропускаются. Поля кроме
тела и источников сохраняются, новая редакция публикуется поверх прежней,
не удаляя её. Непубличная цель новой ссылки отменяет транзакцию. Повтор не
создаёт редакций. Исходные 93 практики и другие режимы импорта не меняются.

Видимые названия источников не выдают широкую публикацию за первоисточник
каждого узкого каталожного названия. Например, документ NCSF описывает классы
образов, но не определяет все отдельные пункты нашего каталога; это явно
пояснено в карточках. В реестре 30 проверенных первичных документов.
Полные тексты/уроки не переводятся и не копируются.


Для редких межбедренного/межгрудного названий используются словарные статьи
Merriam-Webster; для широкого русского «Приватный танец» явно обозначено отличие
от более узкого английского lap dance. Scarleteen и Options for Sexual Health
использованы для различения форм близости. Cleveland Clinic подтверждает
разделение сексуального контекста простаты и недоказанных лечебных обещаний.
NHS рассматривает термическое/холодовое повреждение, а не параметры практик;
Sklar описывает конкретный инструмент, а производители — конкретные классы и
модели. Рекламные обещания не перенесены в Wiki.

Исследование щекотки Kamiloğlu et al. (2024), DOI 10.1098/rsbl.2024.0543,
проверено по аннотации через открытый XML Europe PMC. Это исследование смеха
и контроля голоса, а не согласия. В ledger указаны фактический способ доступа
и проверенный раздел. Недоступные текстовому ридеру NHS inform и закрытая
словарная страница Taber’s не представлены прочитанными источниками.

## Проверка исходных материалов девайсов

Первый проверенный блок `device-reviews-v1` содержит 22 записи и 17 первичных
каталожных страниц. Для ударных инструментов, манжет, ремней, портупей, мебели,
повязки, кляпа и позиционных подушек явно выделены конструкция/класс и пределы
подтверждения. Коммерческий каталог не используется как медицинское заключение,
расчёт нагрузки или универсальная инструкция. Исходный `devices-v1` сохранён.
Итоговую поставку возвращает `load_reviewed_device_articles`; её же читает аудит.

Команда `--refresh-devices` применяется после исходных девайсов и обзорных статей.
Она обновляет только точную исходную публикацию версии 1 либо неизменённую
цепочку заглушка → исходная статья версии 2. Проверяются тело, метаданные,
миниатюра и связи с практиками/позами/девайсами. Черновики, архив, переносы и
ручные изменения пропускаются; новая редакция сохраняет прежнюю историю.
Недоступная читателю цель ссылки отменяет всю транзакцию. Административная
проверка, общая блокировка Wiki и блокировки страниц защищают обновление;
повтор без изменений не создаёт редакций. Схема и API остаются прежними.

## Проверка исходных материалов поз

`pose-reviews-v1` дополняет все 106 исходных карточек: 26 источников с указанной
областью подтверждения и 436 переходов. Для каждой карточки есть сравнение с
двумя близкими положениями, обзор и статья категории; 12 карточек дополнительно
связаны с девайсами. Типизированные ссылки содержат kind и uid; UUID из другого
справочника не принимается. Итоговую поставку возвращает
`load_reviewed_pose_articles`, исходный `poses-v1` остаётся историческим корпусом.

Команда `--refresh-poses` выполняется после импорта исходных поз, обзорных статей
и дополнительных каталогов. Проверяются точные исходное тело, метаданные,
миниатюра, связанные девайсы и история версии 1 либо заглушка → статья версии 2.
Черновики, архивы, перемещения и правки пропускаются. Обновление атомарно,
под административной проверкой и блокировками Wiki/страниц; непубличная цель
или ссылка не на тот справочник отменяет всю транзакцию. Повтор не создаёт редакций.

Названия современных вариантов не объявлены древними или общепринятыми.
Словарь подтверждает пространственный термин, публикации о семействах — лишь
базовую ориентацию, документы производителей — предмет опоры. Gorean Codex
используется как фанатская интерпретация литературного мира. Противоречивая
подпись Tower в современной публикации Kneel не заимствуется. Закрытые WebMD
и нестабильно доступный Blogspot не заявлены как прочитанные подтверждения.
Новые иллюстрации, лечебные режимы и техники стимуляции не добавляются.
