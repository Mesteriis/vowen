# Профиль участника — фактический результат

2026-10-18. Ветка feature/participant-profile. Коммитов, push, production-деплоя и сборок приложения не было.

## Реализовано

- Backend: `/api/v1/me/profile`, GET/PUT/DELETE `/me/profile/draft`, POST `/me/profile/publish`, GET `/participants/{owner_id}/profile`. Для DELETE нужна версия, для PUT — ожидаемая версия и данные раздела, для publish — версия черновика.
- Данные справочников связаны настоящими FK; неизвестные/неподходящие UUID и дубли отвергаются. Пропуск поля сохраняет прежнее значение; пустые списки и null очищают соответствующие поля.
- Публикация блокирует владельца и проверяет версии профиля/аккаунта; устаревшая вкладка получает 409. Отдельный черновик переживает повторный вход и не доступен другим участникам.
- Разделы приватны по умолчанию. Читатель выбирается явно среди прямых активных отношений, grant связан с relation UUID. Пауза/отзыв закрывают чтение; новая связь не открывает прежние сведения. Администратор и Dominant не обходят правила.
- Web: личный паспорт, каталог предпочтений, независимый опыт/участие, табу и условия, здоровье/забота, видимость; необязательный мастер из 6 шагов. Обычный редактор и мастер используют один draft и API.
- Android: соответствующие исходники API/state/Compose, подключение к профилю и тесты. Сборка и устройство не проверены.

## Проверено

- Полный backend: 313 passed, PostgreSQL, 110.12s. Первый запуск без PATH venv дал 308 passed / 2 migration failures из-за недоступного `alembic`; повтор этих двух тестов прошёл, затем полный запуск с правильным PATH прошёл 313/313. Проверки не удалялись.
- Web: 39 Vitest, vue-tsc, ESLint. Backend ruff, mypy 93 файла. Контракт и static assets — отдельные успешные проверки.
- Новый Playwright scenario с реальным API: 1 passed, включает 390/768/1024/1440px, черновик после reload, реальные записи практик, независимые атрибуты, publish, переход редактор→мастер, disabled inputs во время PUT, сохранение текста при network failure. Другие старые E2E-файлы повторно не прогонялись.
- Независимый свежий review выявил 6 Important ошибок: привязка доступа к старым отношениям, потеря текста при переходе в мастер, ловушка неактивного читателя, потеря пропущенных полей, изменение полей во время запроса, отсутствие практик в shared boundaries. Исправлены; соответствующие HTTP/клиентские регрессии проходят.
- Визуальная проверка Web: design-qa.md; source/implementation сравнивались вместе. Реальная виртуальная клавиатура телефона и native Android не проверены.

## Решения и стоимость отклонений от плана

1. Сохранён текущий preview checkout, создана feature-ветка вместо отдельного worktree. Это сохраняет настроенный debug; риск — параллельные изменения используют ту же рабочую папку. Посторонние изменения не перезаписывались.
2. Коммиты и удаление рабочего ledger не выполнялись из-за запрета пользователя. Риск — незакоммиченные результаты нужно сохранять до очистки checkout.
3. Однотипные таблицы выбранных справочников объявлены фиксированным отображением конкретных FK, без polymorphic UUID. Добавление нового вида требует явного изменения модели и миграции.
4. К уже применённой в preview 0044 добавлена отдельная 0045 для relation-bound grants. Это сохраняет данные и требует дополнительного шага миграции; старые grants без привязки остаются закрыты до явного повторного открытия.

Отложенных Minor замечаний reviewer не вернул. Android acceptance остаётся незавершённой проверкой, а не пройденным этапом. Личная фотозагрузка аватара не входила в согласованный срез; используется монограмма.
